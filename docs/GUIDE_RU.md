# Как пользоваться и разбирать проект

Это первая версия инструмента для наблюдений о безопасности Arch Linux. Сначала запусти учебный режим: он ничего не проверяет на твоём компьютере, все данные вымышлены.

## 1. Запуск

Открой терминал в папке проекта — там, где лежит README.md:

```bash
python -m arch_security_audit --demo
```

Каждая запись содержит статус, обнаруженные факты, пояснение `Why` и следующий шаг `Next`. Например, `passwordauthentication=yes` означает, что в базовом конфиге SSH разрешены пароли. Нужно понять, нужен ли такой вход. Для отключения паролей сначала проверяют вход по ключу. Программа ничего не меняет.

## 2. Проверка твоей системы

```bash
python -m arch_security_audit
```

Значения статусов:

- `INFO`: инструмент собрал сведения; это не оценка «всё безопасно».
- `WARN`: есть повод разобраться с настройкой.
- `UNKNOWN`: проверить не получилось, например не хватило прав или нет утилиты.
- `SKIP`: проверка пропущена намеренно.
- `PASS`: конкретная узкая проверка прошла, например checkupdates не сообщил обновлений.

Для начала достаточно обычного пользователя. Отсутствие nft или sshd не требует немедленно их устанавливать. Если SSH-сервер не нужен, запускать его ради аудита тоже не нужно.

После изучения исходников можно отдельно выполнить проверки firewall и SSH с правами root:

```bash
sudo /usr/bin/python -m arch_security_audit --only firewall ssh
```

Команда предполагает, что ты находишься в доверенной папке проекта, а системный Python расположен в `/usr/bin/python`, как в обычной установке Arch.

Обновления проверяются отдельной командой от обычного пользователя:

```bash
python -m arch_security_audit --only updates --online
```

Нужен `checkupdates` из pacman-contrib. Этот режим обращается к зеркалам и создаёт отдельную временную базу пакетов; установленную систему не обновляет. По умолчанию сеть не используется. Под root онлайн-проверка пропускается. Доступные обновления сами по себе не означают наличие известных уязвимостей.

## 3. Отчёт JSON

```bash
python -m arch_security_audit --format json > audit-report.json
```

JSON удобно обрабатывать программами. Поле `demo` позволяет отличить учебный вывод от настоящего. Реальный отчёт может содержать имена пользователей, пути и версии пакетов. Перед публикацией просмотри его; для README лучше использовать демо.

## 4. Как устроен код

- `arch_security_audit/__main__.py` — вход при запуске через `python -m`.
- `cli.py` — аргументы, сбор результатов и вывод текста/JSON.
- `checks.py` — пять проверок и запуск системных команд.
- `tests/test_audit.py` — проверки логики на вымышленных данных и временных файлах.

Начни с функции `updates`: она короткая, показывает обработку аргументов, кодов возврата и ограничений. Затем разбери `ssh`. Словарь `CHECKS` связывает имена команд с функциями.

Для каждой проверки используется `Finding`: имя, статус, заголовок, факты, объяснение и рекомендация. Это помогает сохранить единый формат при добавлении новых проверок.

Запуск тестов:

```bash
python -m unittest discover -s tests -v
```

## 5. Что можно улучшить самому

1. Проверить версию 0.1.0 в своей Arch VM и описать реальные ограничения.
2. Добавить отдельные факты о цепочках IPv4 и IPv6, сохранив осторожность с выводами.
3. Добавить параметры контекста для `sshd -T -C`, чтобы учитывать Match.
4. Сделать русскую локализацию CLI.

Важная часть портфолио — уметь объяснить, почему неизвестный результат не считается успешной проверкой и почему найденный SUID-файл не объявляется вредоносным.

## 6. Публикация на GitHub

После проверки на своём Arch создай пустой репозиторий `arch-security-audit` без автоматически добавленных README и лицензии. В папке проекта выполни:

```bash
git init -b main
git add .
git diff --cached --stat
git commit -m "Initial release: evidence-based Arch security checks"
```

Затем добавь адрес именно своего нового репозитория, заменив YOUR_USERNAME:

```bash
git remote add origin https://github.com/YOUR_USERNAME/arch-security-audit.git
git push -u origin main
```

Для HTTPS понадобится настроенная авторизация GitHub; пароль аккаунта для git push не используется. Альтернатива — настроить SSH и взять SSH-адрес из GitHub. Не вставляй токены в README или адрес remote.

Лицензия MIT уже включена; можешь добавить своё имя в строку copyright, когда выберешь публичное имя автора. CI после первого push должен запуститься автоматически. Его результат нужно проверить на GitHub: локальные тесты не означают, что CI уже прошёл.
# Сравнение отчётов (0.2.0)

Сохраните два запуска с `--format json` в `before.json` и `after.json`, затем выполните:

```bash
python -m arch_security_audit --compare before.json after.json
```

Сравнение не запускает системных команд. Используйте одинаковый набор проверок на одном компьютере. Программа проверяет совпадение дистрибутива и признака демо, но не может установить личность компьютера. `removed` означает отсутствие проверки во втором отчёте. `WARN -> UNKNOWN` означает потерю наблюдения; `WARN -> INFO` означает изменение статуса, но не доказанное исправление. Для автоматической обработки добавьте `--format json`. Код 0 означает успешное сравнение, код 2 — ошибку входных файлов.
